---
title: Backup and restore
description: How to back up your Message Vault data and restore it on another machine.
---

Message Vault keeps everything in two places: a SQLite database file (`vault.db`) and a `data/` directory of per-account asset folders. Backing up both is straightforward.

## What to back up

| Item | Path | Contents |
|------|------|----------|
| Database | `data/vault.db` | All messages, conversations, contacts, labels, accounts, tokens, preferences, trash, import history |
| Assets | `data/<account_id>/<source_id>/assets/` | Original attachments (photos, videos, audio, documents) |
| Converted media | `data/<account_id>/<source_id>/assets_converted/` | Browser-friendly versions generated by `process-assets` |
| Config | `config/config.toml` | Paths and server bind settings |

The converted media can be regenerated with `process-assets` after a restore, so omitting it from a backup is safe if the backup size is a concern.

## Back up a Docker volume

```bash
docker run --rm \
  -v message-vault-data:/data \
  -v "$PWD":/backup \
  alpine tar czf /backup/vault-backup-$(date +%Y%m%d).tgz -C /data .
```

This creates a timestamped tarball in your current directory containing the full contents of the named volume.

## Back up the database safely

SQLite uses write-ahead logging (WAL). For a consistent snapshot without stopping the server:

```bash
sqlite3 data/vault.db "VACUUM INTO 'vault-backup.db'"
```

The `VACUUM INTO` command writes a clean, self-contained copy. If `sqlite3` is not on your path, you can also copy `vault.db`, `vault.db-wal`, and `vault.db-shm` together while the server is stopped.

## Back up a native (non-Docker) installation

Stop the `serve` process, then copy everything:

```bash
# Stop the server first (Ctrl+C in its terminal)
tar czf vault-backup-$(date +%Y%m%d).tgz data/ config/config.toml
```

## Restore

### Docker

```bash
# Stop the running container
docker stop message-vault
docker rm message-vault

# Create a fresh volume and extract the backup into it
docker volume rm message-vault-data
docker volume create message-vault-data
docker run --rm \
  -v message-vault-data:/data \
  -v "$PWD":/backup \
  alpine tar xzf /backup/vault-backup-20250805.tgz -C /data

# Restart
docker run -d --name message-vault \
  -p 3000:3000 -p 8080:8080 \
  -e VAULT_MODE=personal \
  -v message-vault-data:/app/data \
  mbeisser1/message-vault:latest
```

### Native

```bash
tar xzf vault-backup-20250805.tgz
cargo run --release -- serve &
cd web && npm run dev &
```

## Moving to a new machine

The vault is self-contained. Copy the backup tarball to the new machine, extract it, and start the vault with the same config and data paths. All accounts, messages, and attachments transfer as-is.

If you are moving from a native installation to Docker, copy `data/` and `config/config.toml` into the Docker volume. The paths inside `config.toml` may need updating if the Docker layout differs.

## Exporters — no backup needed

Exports from the Message Exporters desktop app are ordinary files. Copy them like any other file. There is no database, no state, and nothing to migrate.
